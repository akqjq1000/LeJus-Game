# LeJus Game

> 도트 그래픽 2D 횡스크롤 솔로 플레이 액션 게임 (모바일 · PC)

캐릭터는 **자동으로 기본 공격**을 하고, 플레이어는 **방향 커맨드를 입력**해 스킬 공격과 회피를 펼칩니다.
짧은 커맨드 입력 타이밍으로 전투의 손맛을 느끼는 것이 핵심 재미입니다.

## 3. 플레이 방식

사냥터와 보스방에 적용되는 전투 규칙입니다.

### 이동

- **적군(Enemy)은 자동 이동**하며 플레이어에게 다가옵니다.

### 공격

| 종류 | 설명 |
| --- | --- |
| 기본 공격 | 캐릭터가 자동으로 수행 |
| 커맨드 스킬 공격 | 방향 커맨드를 입력해 스킬 발동 |

### 입력 방식

| 플랫폼 | 커맨드 입력 |
| --- | --- |
| PC | 방향키(← → ↑ ↓) |
| 모바일 | 화면 상·하·좌·우 영역 터치 |

## 5. 스킬

| 스킬 | 커맨드 | 효과 |
| --- | --- | --- |
| 백스탭 | `← ←` | 뒤로 빠르게 이동 (회피) |
| 돌진 | `→ →` | 앞으로 빠르게 이동 |
| 멀티샷 | `→ ← →` | 공격 범위 내 적 최대 3명에게 강한 공격 |
| 화살비 | `↑ → ↓` | 최대 사정거리에 화살 5발이 하늘에서 떨어지는 공격 |

> 스킬은 **경험치**로 획득하고 강화합니다.

## 8. 추천 프레임워크 및 기술 스택

### 결론: Godot 4 (GDScript)

1인/소규모 인디 팀이 **도트 2D 횡스크롤 게임을 모바일과 PC에 동시에 출시**하기에 가장 균형이 좋은 선택으로 **Godot 4**를 추천합니다.

| 이유 | 설명 |
| --- | --- |
| 2D 전용 엔진 | 2D가 3D 위에 얹힌 구조가 아니라 별도 2D 렌더러를 갖고 있어 픽셀 단위 좌표, 픽셀 스냅, 정수 배율 스케일링을 기본 설정으로 지원 |
| 멀티 플랫폼 빌드 | 하나의 프로젝트로 Windows · macOS · Linux · Android · iOS · Web 내보내기 |
| 입력 추상화 | Input Map에 방향키와 터치 영역을 같은 액션(`cmd_left` 등)으로 묶을 수 있어 커맨드 판정 로직을 플랫폼별로 따로 짤 필요가 없음 |
| 비용 | MIT 라이선스, 로열티·런타임 요금 없음 |
| 가벼움 | 에디터·빌드 용량이 작고 실행이 빨라 저사양 모바일에서도 유리 |
| 학습 곡선 | GDScript는 Python과 비슷한 문법이라 빠르게 익힐 수 있음 |

### 도트 그래픽 설정 가이드 (Godot)

- **기준 해상도**: 예) `640×360` (16:9, 정수 배율로 1280×720, 1920×1080 확장)
- `Project Settings > Display > Window > Stretch`
  - Mode: `viewport`, Aspect: `keep_height` (또는 `expand`), Scale Mode: `integer`
- `Rendering > Textures > Canvas Textures > Default Texture Filter`: **Nearest**
- `Rendering > 2D > Snap 2D Transforms to Pixel`: **On**

### 커맨드 입력 구현 아이디어

1. PC 방향키와 모바일 화면 4분할 터치를 동일한 입력 액션(`cmd_left`, `cmd_right`, `cmd_up`, `cmd_down`)으로 매핑
2. 입력을 시간과 함께 버퍼(최근 N개)에 저장
3. 마지막 입력 후 일정 시간(예: 0.4초) 안에 이어진 입력만 하나의 커맨드로 인정
4. 긴 커맨드부터 우선 매칭 (`→ ← →` 멀티샷이 `→ →` 돌진보다 먼저 판정되도록 대기 시간 고려)
5. 매칭되면 스킬 발동, 실패하면 버퍼 초기화

```
└── tests/
```

## 9. 개발 로드맵 (안)

1. **프로토타입**: 궁수 자동 공격, 일반 몬스터 자동 이동, 커맨드 입력 판정, 스킬 4종
2. **맵**: 광장(자유 이동) ↔ 사냥터 ↔ 보스방 전환
3. **성장**: 골드·다이아·경험치 획득, 스킬 획득/강화, 상점
4. **스탯**: 체력, 공격력, 치명 확률 도입
5. **플랫폼 대응**: 모바일 터치 UI/가상 패드, 해상도 대응, 저장
6. **출시 준비**: 사운드, 밸런싱, 스토어 빌드 및 배포
